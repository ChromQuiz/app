# 機能一覧(確認用)

このアプリの全機能を、確認のために洗い出した一覧です。2026-10-03 時点のコードを読んで書いています(推測ではなく、コードにある条件と数値だけを書き、確認できなかったものは「要確認」としました)。

- 各項目は `- [ ]` のチェックリストです。「何を」「どの条件で」「どうなるべきか」の順で書いています。
- 項目の ID(例: `ENT-07`)は、確認の記録や不具合の報告で使ってください。
- 末尾の「検出事項」は、洗い出しの途中で見つけた、挙動や文言の疑問点です。
- 一覧の抜け漏れは、画面の ID・Edge Function の動作・DB の関数・API のメソッドを機械的に拾って、この文書に出てくるかを確認しています(末尾の「網羅の確認」)。

## 0. 前提となる定義

### 0-1. 役割

| 役割 | どうやって入るか | できること |
|---|---|---|
| 未ログイン | — | エントリー、エントリーリスト、参加規約、ヘルプ、マイエントリー(メール+パスワード) |
| 参加者 | マイエントリーでメール+パスワード。30分の短命トークン(操作のたびに延長) | 自分のエントリーの確認・変更・遅刻連絡・キャンセル・成績照会 |
| 採点者(scorer) | Google ログイン + 招待リンク | 採点画面、当日受付(カメラ) |
| 管理者(admin) | Google ログイン(所有者が権限を付与) | 運営画面のすべて(メンバー管理は所有者以外を対象) |
| 所有者(owner) | プロジェクトを作った人 | 管理者と同じ。権限を変更・外す対象にならない |

### 0-2. エントリーの状態

- 状態: `registered`(登録済み)/ `waitlist`(キャンセル待ち)/ `late`(遅刻連絡あり)/ `canceled`(キャンセル済み)。これとは別に `checked_in`(当日受付済み)のフラグがあります。
- 作成直後は `registered`。定員を超えると、再計算で `waitlist` になります。
- 遅刻の連絡: `registered` かつ未受付で、**エントリーの受付が終わっている(終了後または停止中)**ときだけ `late` になります。受付中は、代わりに内容の編集ができます。
- キャンセル: 未受付で、`canceled` でないときだけできます。キャンセルすると再計算が走り、条件を満たせばキャンセル待ちの先頭が繰り上がります。
- 受付済み(`checked_in`)の人は、編集・遅刻連絡・キャンセルがすべてできなくなります(運営への連絡を案内)。
- 運営は、受付を取り消す(`checked_in` を戻す)ことができます。

### 0-3. 定員と優先ルール(再計算 `recompute_entry_statuses`)

- 並び順: ①開始から24時間以内かつ中部地方 → ②開始から24時間以内かつ中部以外 → ③24時間より後(中部かを問わず)。各区分の中はエントリー順(作成日時、受付番号)。
- `period_start` が未設定の大会は、優先枠を使わず、全員先着順です。
- 定員(`max_entries`): 0 以下は無制限。順位が定員以内なら `registered`(遅刻連絡済みなら `late`)、超えると `waitlist`。受付済みの人は状態が固定されます。
- 再計算が走るとき: エントリー作成、キャンセル、プロジェクトの `max_entries` または `period_start` の更新。
- キャンセル待ちの繰り上げは、繰り上げ期限(未設定ならエントリー終了日時)までの間だけ有効です。繰り上げられた人には、運営の画面を開いたときに通知メールが送られます(通知状態: pending → sending → sent / failed)。
- エントリーリスト画面(`calcPriority`)にも同じ規則の実装があります。サーバーと同じ結果になるか、確認が必要です。

### 0-4. 時間の窓と数値

| 項目 | 値 | 場所 |
|---|---|---|
| 認証コードの有効時間 | 10分 | send-email |
| 認証コードの再送の待ち時間 | 60秒 | entry.js |
| メール認証後のフォーム保持 | 10分(画面側)/ トークン30分(サーバー側) | entry.js / email_verify.ts |
| 参加者トークン | 30分(操作のたびに延長) | participant_auth.ts |
| 二次元コード | 有効期限なし(旧形式は発行から30日まで有効) | qr_token.ts |
| 認証コード送信のIP制限 | 10分に5回 | rate_limit.ts |
| 同一宛先・同一テンプレートのメール | 認証コードは10分に5通、それ以外は10通 | send-email |

| エントリー作成のIP制限 | 1時間に10回 | rate_limit.ts |

## A. 入口(ログイン・大会の作成・採点者の参加)

### A-1. ログイン画面(`index.html`)

- [ ] **IDX-01 表示** — 未ログイン: 「ログイン」と「Googleで続行」。ヘルプへのリンク。
- [ ] **IDX-02 Googleログイン** — 「Googleで続行」→ Google の認証 → 戻ると、自分が参加している大会の一覧が出る。認証前の意図(参加か作成か)が保存され、戻ったあとに復元される。
- [ ] **IDX-03 ログイン失敗** — Google を開始できない場合: 「Googleログインを開始できませんでした」+ 詳細。6秒で消える(設定不備は残る)。
- [ ] **IDX-04 file:// で開いた場合** — 公開URLへ移動する。または、開始できない旨のメッセージ。
- [ ] **IDX-05 大会の一覧(参加している大会)** — 自分がメンバーの大会が並ぶ。0件のときの表示。大会ごとに役割(所有者・管理者・採点者)が出る。
- [ ] **IDX-06 大会に入る** — 一覧から選ぶ → 役割が scorer なら採点者、それ以外は管理者として `judge.html` へ。セッション(大会ID・名前・役割)が保存される。
- [ ] **IDX-07 ログアウト** — 「ログアウト」でGoogleのセッションを破棄。失敗時はメッセージ(詳細つき)。
- [ ] **IDX-08 採点者向けの案内** — 「採点者として参加するには、運営から共有された招待リンクを開いてください」。
- [ ] **IDX-09 大会の作成(`#create`)** — URL末尾の `#create` でのみ「新しい大会」が表示される。ログイン済みのとき、「回数」を入力して「プロジェクトを作成」。
  - 回数が空・0以下: 「回数を入力してください」。
  - 未ログイン: 「先にGoogleアカウントでログインしてください」。
  - 作成中はボタンが無効化され、「作成中…」。
  - 成功: プロジェクトID `ciq{回数}`、名前 `CIQ the {回数}{序数}`(1st、2nd、3rd、4th…11th〜13th は th)。RSA鍵ペアを作り、公開鍵・暗号化した秘密鍵・所有者を保存。秘密鍵は自動で保管され、セッションにも保持される。
  - 同じ回数がすでにある: 「既に存在します」のメッセージ。
  - 成功後: 「プロジェクトを作成しました」+「運営をはじめる」。
- [ ] **IDX-10 作成モードの戻り導線** — 作成モードでは「ログインに戻る」が出る。タイトルは「大会をつくる」。
- [ ] **IDX-11 大会の一覧の読み込み失敗** — 「プロジェクトを読み込めませんでした」。

### A-2. 採点者の参加(`join.html?t=…`)

- [ ] **JOIN-01 招待リンクなし** — トークンが無い: 「招待リンクが正しくありません」。
- [ ] **JOIN-02 未ログインで開く** — 「Googleで続行」が出る。押すと Google の認証 → 戻ったあとにトークンが sessionStorage に残っていて、自動で参加処理に進む。
- [ ] **JOIN-03 ログイン済みで開く** — 自動で参加処理。成功: 「◯◯ に採点者として参加しました」+「採点画面へ進む」。
- [ ] **JOIN-04 すでに参加している人** — 「◯◯ にはすでに参加しています」。使用人数を消費しない。
- [ ] **JOIN-05 リンクが使えないとき** — 期限切れ / 使用上限 / 無効化(失効)/ 外されたメンバー / 形式不正で、それぞれのメッセージ(運営に新しいリンクを依頼)。ボタンは消える。
- [ ] **JOIN-06 Google認証が開始できない** — 「Googleログインを開始できませんでした」+ 詳細。
- [ ] **JOIN-07 サーバーに接続できない** — Supabase設定が無い、またはその他。
- [ ] **JOIN-08 並列に使う** — 上限人数ちょうどのリンクに多数が同時に参加しても、上限を超えない(本番で実測済み: 10並列で2件のみ成功)。
- [ ] **JOIN-09 「採点画面へ進む」** — `judge.html` へ。セッションが設定されている(役割は scorer)。

## B. エントリー(`entry.html`)

### B-1. 表示の条件

- [ ] **ENT-01 大会が指定されていない** — `pid` なし: 「大会が指定されていません」+ 正しいURLを案内。フォームは出ない。
- [ ] **ENT-02 大会が存在しない** — 「大会が見つかりません」。
- [ ] **ENT-03 受付停止中** — `entry_open = false`: 「エントリーは現在停止中です」+「運営がエントリーを再開するまでお待ちください」。
- [ ] **ENT-04 開始前** — 「エントリーはまだ開始されていません」+ 開始日時(日本語表記)。
- [ ] **ENT-05 終了後** — 「エントリーは終了しました」+ 終了日時。
- [ ] **ENT-06 読み込み失敗** — 通信失敗など: 「大会情報を読み込めませんでした」+「時間をおいて再度お試しください」(内部の英語は出ない)。
- [ ] **ENT-07 大会名** — 見出しとタブのタイトルに大会名(`{大会名} - エントリーフォーム`)。
- [ ] **ENT-08 ステップ表示** — ①本人確認 → ②情報入力 → ③完了。状態に合わせて強調が移る。
- [ ] **ENT-09 再エントリー(`reentry=1`)** — キャンセル済みの人の導線。案内文(新しい受付番号・パスワード・二次元コードが発行される)が出る。

### B-2. メール認証

- [ ] **ENT-10 メールアドレスの入力** — 全角の記号・英数字・空白は半角に直る(入力欄を離れたとき、送信するとき)。
- [ ] **ENT-11 アドレスの形式チェック** — 空: 「メールアドレスを入力してください」。形式が不正(全角が残る、連続ドット、末尾の句点、TLD が1文字、ドメインにアンダースコアなど): 「正しいメールアドレスを入力してください。全角の文字や空白が入っていないかご確認ください」。何も送信されない。
- [ ] **ENT-12 Turnstile(ボット対策)** — ウィジェットが出る。失敗・期限切れ・未取得のとき、サーバーが拒否して「認証を完了できませんでした。ページを再読み込みして…」。送信のたびにリセットされる(ワンタイム)。
- [ ] **ENT-13 認証コードの送信** — 「認証コードを送信」→「送信中…」→ 成功: 「{アドレス} に認証コードを送信しました」+ 迷惑メールの案内、6桁入力欄が出る、メール欄は固定、送信ボタンは消えて再送ボタンが出る。
- [ ] **ENT-14 送信の失敗(サーバーの理由が出る)** — 次のメッセージが、それぞれの条件で出る(汎用エラーに丸められない)。
  - 10分に5回を超えた: 「認証コードの送信回数が上限に達しました。10分ほど待ってから…」
  - 1日の上限(プロジェクト単位1000通): 「本日のメール送信上限に達しました」
  - 受付停止中 / 開始前 / 終了後 / 大会なし: それぞれの文言。
  - メール会社(Brevo)がアドレスを拒否: 「このメールアドレスには送信できません」
  - メール会社のその他の失敗: 「メールを送信できませんでした。…運営にお問い合わせください」
  - 通信失敗: 「サーバーに接続できませんでした。…」
- [ ] **ENT-15 再送** — 送信直後は「60秒」から減っていくカウントダウン、0 で「再送信」が有効。押すと新しいコードが発行され、以前のコードは使えなくなり、認証済みの状態は破棄される。失敗時: サーバーの理由 or 「認証コードを再送信できませんでした」。
- [ ] **ENT-16 6桁の入力欄** — 6つの欄が、メール欄・ボタンと同じ幅いっぱいに並ぶ。
  - 1桁入力で次の欄へ移る。Backspace で前の欄へ戻って消す。
  - 6桁そろうと、自動で認証される(「認証する」ボタンと同じ動き)。
  - 貼り付け(6桁/桁数が足りない)、1つ目の欄への6桁の自動入力(iPhone のコード候補)で、桁が振り分けられる。
  - Enter で認証。数字以外は入らない。
  - iPhone のコード候補をタップして、6桁が入り、そのまま認証が通る(実機で確認済み)。
- [ ] **ENT-17 認証する** — 空: 「認証コードを入力してください」。6桁未満: 「6桁の認証コードを入力してください」。成功: フォームが開き、確認済みのメールが表示される。
- [ ] **ENT-18 認証の失敗** — コードが違う / 期限切れ(10分)/ 別のメールで発行したコード: 「認証コードが正しくないか、有効期限が切れています。入力内容をご確認いただくか、認証コードを再送信してください」。認証済み状態は破棄される。
- [ ] **ENT-19 認証後のメール変更** — 認証済みになった後でメール欄が変えられた場合、認証済み状態とトークンが破棄される。
- [ ] **ENT-20 29分でリセット** — 認証から29分たつと、フォームが閉じて本人確認に戻る(「セッションの有効期限が切れました」)。サーバー側のトークンは30分有効で、それより少し短くしてある。
- [ ] **ENT-21 認証前に「エントリーを確定する」を押す** — 状況に応じた案内(メール未入力 / コード未入力 / コード確認 / 送信を促す)。

### B-3. 入力フォーム

- [ ] **ENT-22 氏名** — 姓・名(必須、全角の案内)。
- [ ] **ENT-23 カナ** — セイ・メイ(必須)。全角カタカナ(`ァ-ヴー`)のみ。違う場合: 「カナは全角カタカナで入力してください」。
- [ ] **ENT-24 所属教育機関** — 必須・「公開」タグ。非公開にしたい場合は「非公開」と入力する案内。
- [ ] **ENT-25 学年** — 必須。選択肢: １年〜６年、非公開(全角数字)。
- [ ] **ENT-26 中部地方チェック** — 中部10県(愛知・岐阜・三重・静岡・長野・山梨・新潟・富山・石川・福井)。「エントリー開始から24時間は中部地方の方が優先」の説明が出る。
- [ ] **ENT-27 エントリーネーム** — 必須・「公開」。**本名についての注意書きが、赤の太字とアイコンで目立つ**(ダーク・ライト両方で読める)。
- [ ] **ENT-28 意気込み(任意・公開)、運営への連絡(任意・非公開)** — 長い入力、改行。
- [ ] **ENT-29 参加規約への同意(「参加規約に同意し、入力した情報が正確であることを確認しました。」)** — 必須。リンクは `terms.html?pid=…`。
- [ ] **ENT-30 確認サマリー** — 折りたたみを開くと、入力内容(氏名、カナ、所属/学年、中部、エントリーネーム、意気込み、運営への連絡)が一覧で出る。空欄は「—」。
- [ ] **ENT-31 必須項目の未入力** — ブラウザの必須チェックで止まる。

### B-4. 送信と完了

- [ ] **ENT-32 送信中** — ボタンは無効化され「処理中…」。二重送信できない。
- [ ] **ENT-33 送信** — 個人情報(氏名・カナ・メール)をプロジェクトの公開鍵(RSA)で暗号化し、パスワード(8文字、英数字、紛らわしい文字を除く)を自動生成してハッシュ化し、`create-entry` へ送る。
- [ ] **ENT-34 サーバーの拒否** — メール認証が確認できない(400/401)/ Turnstile 失敗(403)/ すでに同じメールでエントリー済み(409)/ 受付停止(403)/ 開始前 / 終了後 / 1時間に10回(429)。それぞれ日本語のメッセージ。失敗後も、再度送信できる(Turnstile がリセットされる)。
- [ ] **ENT-35 成功** — 完了画面: 受付番号(3桁ゼロ埋め)、「メールを保存してください」(二次元コードとパスワードがメールに入る)、「マイエントリーを開く」。
- [ ] **ENT-36 キャンセル待ちの場合** — 完了画面に「定員に達したため、キャンセル待ちとして登録されました。」(時計のアイコンはオレンジ、文字との高さが揃う、下の枠との間隔がある)。
- [ ] **ENT-37 確認メール** — 登録後に確認メールが送られる(失敗しても画面は完了のまま)。
- [ ] **ENT-38 同じメールで二重登録** — 有効なエントリーがあるあいだは拒否される。キャンセル後は再登録できる。
- [ ] **ENT-39 受付番号の採番** — 大会内で連番(`last_entry_number + 1`)。同時に登録しても重複しない。
- [ ] **ENT-40 定員の判定** — 定員内なら登録済み、超えるとキャンセル待ち。中部優先枠の並び(0-3)に従う。開始前・終了後・停止中はサーバーでも拒否される。

## C. マイエントリー(`my.html?pid=…`)

### C-1. ログインとセッション

- [ ] **MY-01 大会が指定されていない** — 「大会が特定できません」+ メールのリンクから開く案内。
- [ ] **MY-02 ログイン** — メールアドレス+パスワード。全角のメールは半角に直ってから検証される。ブラウザ標準の検証で止まらない。
- [ ] **MY-03 ログイン失敗** — 不一致: 「メールアドレスまたはパスワードが正しくありません」。失敗の回数制限(IP単位)に達すると「試行回数が上限に達しました」。
- [ ] **MY-04 ログイン成功** — 受付番号、状態バッジ、二次元コード、エントリー内容が出る。
- [ ] **MY-05 セッションの保持** — タブを開いている間は sessionStorage のトークンで再認証なしに復帰。30分(操作のたびに延長)で失効し、「セッションの有効期限が切れました。もう一度ログインしてください」で再ログイン。トークンのエントリーが見つからない場合は「エントリーが見つかりません」。
- [ ] **MY-06 ログアウト** — 「ログアウト」でセッションを破棄し、ログイン画面に戻る。共有端末の注意書き。
- [ ] **MY-07 サーバー設定の障害** — 署名鍵・ペッパーの未設定時: 「ただいまこの操作を受け付けられません」。

### C-2. 表示

- [ ] **QST-02 模範解答の表示** — 問題番号と、主答え。別解があれば主答えの後ろに並ぶ。
- [ ] **QST-03 答案のカード** — **当日受付を済ませた人**で、答案が保存されている人のカード。受付番号の順。答案の画像(その問題の解答欄)が出る。遅刻の連絡だけの人、キャンセル済み・キャンセル待ちの人は出ない。画像がないとき: 「答案データがありません」。
- [ ] **QST-04 画像の用意** — 最初の数件を先に読み込み、残りを裏で読み込む。解答欄の切り出し画像が未生成なら、ページ画像から切り出して表示し、切り出した画像を保存する(次回以降は速い)。読み込みに失敗した画像は代替の取得を試みる。
- [ ] **QST-05 判定** — 「正解」(M)/「不正解」(X)/「保留」(H)のボタンとキー。判定すると、そのカードに印が付き、次のカードへ移る。矢印キーでカード間を移動(上下は列数ぶん)。選択中のカードが画面内に収まるようにスクロールする。
- [ ] **QST-06 保存** — 判定は1件ずつサーバーに保存される。保存に失敗したら「採点を保存できませんでした（詳細: …）」+ 画面を最新に戻す。保存を待たずに次の判定ができる。
- [ ] **QST-07 自分の判定だけが見える** — 他の採点者の判定は、採点画面には出ない。
- [ ] **QST-08 進捗** — 「◯ / ◯ 件」。すべて判定すると緑(「保留」も判定済みとして数える)。
- [ ] **QST-09 自動完了** — すべての答案に判定を付けると、自動で「この問題の採点を完了」になり、次に入れる問題へ移る。完了した問題に戻ると、判定は残っているが再度完了にはならない。
- [ ] **QST-10 初期の選択位置** — 最初に開くとき、判定がまだのカードのうち最初のものが選ばれる。
- [ ] **QST-11 キーボードの扱い** — 入力欄にフォーカスがないときだけ M/X/H・矢印が効く。
- [ ] **QST-12 戻る** — 採点ボードへ。
- [ ] **QST-13 離脱した場合** — 途中で画面を閉じても、判定は保存済み。枠は占有されたまま(完了しないと確定が進まない)。採点ボードの「採点中の枠」から解放できる(JDG-10)。
- [ ] **QST-14 確定のしくみ** — 必要人数がすべて完了したとき、答案ごとに「正解が必要人数」または「不正解が必要人数」でそろえば確定。そろわない答案(保留を含む)は「要確認」になる。確定は、当日受付を済ませた人についてのみ記録される。採点が終わったあとで受付した人には確定の記録がなく、点数は 0 になる。

### G-3. 要確認ページ(`conflict.html`、管理者のみ)

- [ ] **CNF-01 入室** — 管理者のみ。採点者は「管理者としてプロジェクトに入室してください」。
- [ ] **CNF-02 一覧** — 判定が割れた答案が、問題番号・受付番号の順に並ぶ。カードに、問題番号、答案の画像、模範解答(と別解)、各採点者の判定(ドット: 正解・不正解・保留)。
- [ ] **CNF-03 件数** — 見出しの横にカウンター。0件: 「要確認はありません」。
- [ ] **CNF-04 最終判定** — 「正解」(M)/「不正解」(X)。決めると、その答案が確定し、カードが消える。選択が次のカードに進む。矢印キーで移動。
- [ ] **CNF-05 自動更新** — 5秒ごとに最新の状態へ(他の人の判定・解決が反映される)。画像は追加分だけ読み込む。
- [ ] **CNF-06 失敗時** — 「要確認データを読み込めませんでした」。最終判定の保存に失敗したときのメッセージ。
- [ ] **CNF-07 戻る** — 戻るボタン。

## H. メール

共通: 件名の先頭は `【大会名】`。HTML(表レイアウト、インラインCSS)とプレーンテキストの両方を送る。ライト・ダークモード、スマホ幅(560px以下)に対応。末尾に「Powered by CIQ / このメールは自動送信されています」。送信は `email_events` に `queued` → `sent` / `failed`(+ 理由)で記録される。送信元は Brevo(既定)、SES を代替として切り替え可能。

- [ ] **MAIL-01 認証コード**(件名 `【大会名】認証コード`)— 「認証コード」の直下に6桁。10分有効の案内、迷惑メール、心当たりがないときは破棄。iPhone のコード候補に出る。
- [ ] **MAIL-02 エントリー受付完了**(`エントリー受付完了（No.◯）`)— 宛名「姓 名 様」、受付番号のカード、パスワード・状態(登録済み/キャンセル待ち)、当日受付用の二次元コード(画像)、「マイエントリー」「エントリーリスト」のボタン、キャンセル待ちの案内。
- [ ] **MAIL-03 エントリー編集完了** — 宛名、「エントリー内容の変更を受け付けました」、受付番号、「マイエントリーを開く」。大会の設定でオフにできる。
- [ ] **MAIL-04 キャンセル完了** — 「エントリーをキャンセルしました」、受付番号、ボタンなし。設定でオフにできる。**宛名の行はない**(氏名を持たないため)。
- [ ] **MAIL-05 遅刻連絡受付** — 「遅刻の連絡を受け付けました」、受付番号、「マイエントリーを開く」。設定でオフにできる。**宛名の行はない**。
- [ ] **MAIL-06 キャンセル待ち繰り上げ** — 「キャンセル待ちから通常エントリーへ繰り上がりました」、受付番号、「マイエントリーを開く」。運営の画面から送られる。設定の対象外。
- [ ] **MAIL-07 二次元コードの画像** — メール内の画像は署名つきURL(`checkin-qr`)。メールを開くたびに新しい二次元コードが作られる(1年キャッシュの指定があり、メールソフトが保存した画像は古い形式のままのことがある)。
- [ ] **MAIL-08 宛先の確認** — 認証コード以外のメールは、宛先のメールがそのエントリーの本人のものであることをサーバーが照合する(ハッシュ)。他人のエントリーIDでは送れない。
- [ ] **MAIL-09 制限** — 認証コードは10分に5通(同じ宛先)、ほかは10通。IP単位(認証コード)10分に5回。プロジェクトで1日1000通(認証コードのみ数える)。
- [ ] **MAIL-10 メール会社の失敗** — アドレス不正(400)は「送信できません」、その他は502「運営にお問い合わせください」。
- [ ] **MAIL-11 配信の実機確認** — Gmail、iPhone のメール、Outlook などでの表示(ダークモード、画像のブロック、ボタンのリンク、二次元コード画像の表示)。
- [ ] **MAIL-12 迷惑メール** — Brevo の送信元ドメインの認証(SPF/DKIM)と、受信箱に入るか。

## I. 公開・認証のAPI(Edge Function)

全関数は `verify_jwt` を無効にして配置し、関数内で認証する。CORS は許可したオリジンだけ。想定外のエラーは汎用の 500(「サーバーで問題が発生しました」)+ 追跡用の ref を返す。

| 関数 | 呼ぶ人 | 動作の種類 | 確認すること |
|---|---|---|---|
| `send-email` | 誰でも(種類によって条件) | `send_verification` / `verify_code` / `entry_confirmation` / `entry_edited` / `entry_cancelled` / `late_notice` / `waitlist_promoted` | 認証コードはTurnstile必須、他は宛先確認。形式不正は400、制限は429 |
| `create-entry` | 誰でも | エントリーの作成 | Turnstile、メール認証トークン、ハッシュの形式、重複(409)、受付外(403)、制限(429) |
| `send-email`(`reset_password`) | 参加者 | メール認証済みトークンで、パスワードを新しいものに差し替え、メールで届ける | 認証コードの確認、登録のないメール、期間外でも使えること |
| `my-entry` | 参加者 | ログイン(メール+パスワード or トークン)と概要・二次元コード | 失敗の制限、30分トークン、`capabilities` の判定 |
| `edit-entry` | 参加者 | 内容の更新 | 受付中・未受付・キャンセル済みでない |
| `cancel-entry` | 参加者 | キャンセル | 受付済みは409、繰り上げの結果が返る |
| `mark-late` | 参加者 | 遅刻の連絡 | 登録済みのみ、重複は409 |
| `disclose-result` | 参加者 | 成績の取得 | 期間内、登録済みか遅刻連絡済みのみ。**英語のエラーが残る**(検出事項) |
| `checkin-qr` | 誰でも(署名つきURL) | 二次元コード画像(SVG)の生成 | 署名なし・不正は404 |
| `check-in` | 採点者以上 | `stats` / `check` | メンバーかつ有効 |
| `check-in` | 管理者以上 | `lookup` / `check_manual` / `undo` | 照会を経た確定だけ |
| `admin-create-entry` | 管理者以上 | 代理登録 | 権限、受付外、重複 |
| `admin-entry-qr` | 管理者以上 | 任意のエントリーの二次元コード | 権限 |
| `project-key` | 管理者以上 | `store` / `fetch`(プロジェクトの秘密鍵の保管) | 権限、404 |
| `create-scorer-invite` | 管理者以上 | 招待リンクの発行 | 上限人数、7日、採点者固定 |
| `redeem-scorer-invite` | Google ログイン済みの人 | 招待リンクで参加 | 期限・上限・無効化・外された人 |

- [ ] **API-01 認証なしで管理系を呼ぶ** — 401(「Googleログインが必要です」)。公開キーだけでは通らない。
- [ ] **API-02 権限のないメンバーで呼ぶ** — 403。外された人・別の大会のメンバーは通らない。
- [ ] **API-03 不正な入力** — 必須項目の欠落・形式不正は400で日本語のメッセージ。
- [ ] **API-04 想定外の失敗** — 500は汎用の文言(内部の詳細は出ない)。
- [ ] **API-05 レート制限** — IP単位(認証コード、エントリー作成、参加者認証、受付の見つからない照会)とプロジェクト単位(メール)。制限の障害時は通す(fail-open)。
- [ ] **API-06 Turnstile** — 認証コード送信とエントリー作成で、ワンタイム・アクション・ホスト名を検証。設定不備のときは受付を止める(fail-closed)。
- [ ] **API-07 秘密の設定の欠落** — 署名鍵・ペッパー・Supabase のシークレット・メールのAPIキーが欠けたとき、503などで止まり、情報を漏らさない。

## J. データベース・ストレージ・リアルタイム

### J-1. テーブル

`projects`(大会と設定)/ `project_members`(メンバーと役割・状態)/ `project_invites`(招待リンク)/ `project_private_keys`(秘密鍵の保管)/ `entries`(エントリー。氏名等は暗号化)/ `public_entry_list`(公開用の一覧。トリガーで同期)/ `public_project_settings`(公開用の設定。同上)/ `answer_pages`(答案ページ)/ `model_answers`(模範解答と別解)/ `question_scorers`(問題ごとの採点者)/ `score_votes`(判定)/ `final_results`(確定結果)/ `score_events`(採点の履歴)/ `email_events`(メール送信の記録)/ `participant_auth_events`(ログイン試行の記録)/ `rate_limit_events`(制限)/ `audit_logs`(監査ログ)。

### J-2. 関数とトリガー

- [ ] **DB-01 `create_entry_atomic`** — 受付外は例外。受付番号の採番と作成が同時実行でも重複しない(ロック)。
- [ ] **DB-02 `recompute_entry_statuses`** — 0-3 の規則。受付済みの状態は変えない。繰り上げの通知状態を `pending` にする。
- [ ] **DB-03 トリガー `projects_recompute_entry_statuses`** — `max_entries` と `period_start` の更新で再計算が走る。
- [ ] **DB-04 `cancel_entry_by_id_atomic`** — 受付済みは拒否。キャンセル後に再計算(期限内なら繰り上げ)。
- [ ] **DB-05 トリガー `entries_sync_public_entry_list` / `projects_sync_public_project_settings`** — 公開用の表に、個人情報を含まない列だけが同期される。
- [ ] **DB-06 `join_question_scorer`** — 必要人数に達していると「満員」。すでに入っている人は何度でも入れる。
- [ ] **DB-07 `set_score_vote`** — 正解・不正解・保留のみ。役割が owner/admin/scorer。判定の更新(上書き)。受付済みでない人の答案には付けられない。問題の枠に入っていなければ、判定を付けた時点で自動で入る。
- [ ] **DB-08 `complete_question_scoring`** — 必要人数が完了したとき、**当日受付を済ませた人**について確定を記録する(`final_results`)。
- [ ] **DB-09 `list_question_answer_cards` / `list_score_conflicts`** — 採点画面と要確認ページ用。いずれも**当日受付を済ませた人**だけ。要確認は管理者のみ。別解を返す。
- [ ] **DB-10a `release_question_scorer`** — メンバーなら誰でも、まだ完了していない枠を解放できる。その人のその問題での判定も消す。完了した枠は例外。行をロックして二重に消えない。監査ログ。
- [ ] **DB-10 `resolve_score_conflict`** — 管理者のみ。最終判定(正解・不正解・保留)を保存し、履歴を残す。
- [ ] **DB-11 `create_project_with_owner`** — 所有者の作成。回数の重複は例外。
- [ ] **DB-12 `update_project_member_role` / `remove_project_member` / `restore_project_member`** — 所有者は変更できない。自分自身は変更できない。
- [ ] **DB-13 `create_scorer_invite` / `redeem_scorer_invite` / `revoke_scorer_invite`** — 平文トークンを保存しない。並列でも上限を超えない。
- [ ] **DB-14 `reset_project_data`** — 管理者のみ。0-4 のとおり。監査ログ。
- [ ] **DB-15 `list_entries_for_admin`** — 管理者のみ。**キャンセル済み・キャンセル待ちも含めて全員**を返す。
- [ ] **DB-16 `rate_limit_hit`** — サービスのみ。排他制御つきで数える。
- [ ] **DB-17 `log_audit_event` / `log_service_event`** — 監査ログ。
- [ ] **DB-24 補助の関数** — `is_project_member`、`has_project_role`、`current_member_id`(権限判定の部品)、`auth_display_name`(表示名)、`touch_updated_at`(更新日時のトリガー)、`recompute_entry_statuses_after_project_update`(DB-03 のトリガー関数)。旧関数 `cancel_entry_atomic` と、採点者の参加コード方式の `join_project_with_scorer_code` は、本番にはもうない(確認済み)。本番には `rls_auto_enable`(Supabase が自動で入れる、新しい表に RLS を有効にするイベントトリガーの部品)もあるが、リポジトリのマイグレーションには無い。

### J-3. 権限(RLS・列の権限)

- [ ] **DB-18 匿名のアクセス** — `entries` の暗号化列・ハッシュ列、`project_private_keys`、招待のトークンハッシュは、匿名では読めない。`public_entry_list` は許可した列だけ(`entry_id` は読めない)。本番のライブテスト25件で確認済み。
- [ ] **DB-19 メンバーの権限** — 採点者が管理系の表・操作を使えない。外された人は何も読めない。採点者・メンバーとしてログインした状態での実測は**未実施**(backlog #1b)。
- [ ] **DB-20 Realtime** — `public_entry_list`、`question_scorers`、`score_votes`、`final_results` が配信対象。画面で使っているのは `public_entry_list`(エントリーリスト)のみ。

### J-4. ストレージ

- [ ] **DB-21 バケット** — `answer-pages`(ページ全体)、`answer-cells`(解答欄の切り出し)。どちらも非公開。署名付きURLで読む。書き込みは管理者のみ。
- [ ] **DB-22 削除** — 答案を削除するとページとセルの画像が消える。リセットでも消える。

### J-5. 監査ログ

- [ ] **DB-23 記録される操作** — `entry.create`、`entry.create_by_staff`、`entry.edit`、`entry.mark_late`、`entry.cancel`、`entry.checkin`、`entry.checkin.undo`、`scorer_invite.create`、`scorer_invite.redeem`、`project_data_reset`。誰が(参加者/運営)、どのIP(HMAC化)で。

## K. 横断(全ページ共通)

### K-1. セッションと認証

- [ ] **CMN-01 運営・採点のセッション** — Google ログイン(Supabase のセッション)。大会ID・名前・役割は **localStorage** に保存され、タブを閉じても残る(共有端末では「プロジェクトから退出」が必要)。採点画面で開いている問題番号(`current_q`)も localStorage。画面の役割判定は表示のためだけで、権限はサーバーで確認される(localStorage を書き換えても権限は増えない)。

## L. セキュリティの確認項目

- [ ] **SEC-01 個人情報** — 氏名・カナ・メールは暗号化(RSA)されて保存され、公開の画面・APIに出ない。復号できるのは、秘密鍵を持つ運営のブラウザだけ。ログに出ない。
- [ ] **SEC-02 非公開バケット** — 答案画像は非公開のまま。署名付きURLの期限。
- [ ] **SEC-03 XSS** — ユーザー入力(エントリーネーム・意気込み・規約・氏名)が、`textContent` で描画される。規約のMarkdownは危険なURLを無効化する。CSP(インラインの実行を許さない)。
- [ ] **SEC-04 CORS** — 許可したオリジンのみ。
- [ ] **SEC-05 ボット対策** — Turnstile(認証コード送信とエントリー作成)。ホスト名の制限。
- [ ] **SEC-06 総当たり** — ログインの失敗の制限、受付の「見つからない」照会の制限、認証コードの送信制限。
- [ ] **SEC-07 二次元コード** — 署名の検証、他の大会では使えない、受付済みは再利用できない、署名鍵を更新すると全員失効。期限はない(2026-10-03 に変更)。本人との照合は受付番号・所属・学年。
- [ ] **SEC-08 招待リンク** — 平文を保存しない、並列でも上限を超えない、期限7日、無効化できる。
- [ ] **SEC-09 サプライチェーン** — 外部スクリプトに SRI(整合性ハッシュ)、バージョン固定。
- [ ] **SEC-10 監査** — 重要な操作が記録される(J-5)。
- [ ] **SEC-11 サーバー側の権限確認** — 画面の判定に頼らず、各関数で毎回確認する(外された人、別の大会、役割)。
- [ ] **SEC-12 秘密のキー** — ブラウザのコードに、サービスロールキー・メールのAPIキー・署名鍵がない。公開用のキー(publishable)のみ。

## M. 運用
